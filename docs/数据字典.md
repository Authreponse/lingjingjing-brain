# 灵鲸鲸数据字典 v1

> 数据库：data/lingjingjing.db；引擎：SQLite，启用 WAL、foreign_keys、busy_timeout=5000。
> 检索：SQLite FTS5，tokenize='trigram'。不上向量库。
> schema_version=1。时间一律保存为带 UTC 偏移的 ISO 8601 文本，显示时才转 Asia/Shanghai；UUID 使用字符串。

## 1. 总体约定

- event 是真相，append-only；state 是可重放的投影。禁止通过修改或删除事件“修正历史”，修正只能追加新事件。
- memory 保存可迁移的事实，不保存大段聊天原文。当前对话原文可作为 user.message / assistant.message 的事件证据，但不等于长期记忆。
- payload、evidence_ids、basis_ids 在 SQLite 中以 JSON 文本保存，读出后解析；数组里只放可追溯 ID。
- 所有写操作在事务中完成。业务表变更与对应 event 必须同时成功或同时回滚。
- 不在任何 payload 中保存密码、验证码、API 密钥或完整登录态。安全事件只记来源、时间、类别和处置。

## 2. 通用字段

| 类型/字段 | 含义 | 约束 |
|---|---|---|
| id | 实体标识 | UUID 字符串，主键 |
| ts / created_at / updated_at | UTC 时间 | 文本，例如 2026-10-31T13:00:00.000+00:00 |
| actor | 事件行为者 | 主人、灵鲸鲸、system 等稳定名称 |
| kind | 类型 | 小写点分事件名或受控枚举，不用自由长句 |
| weight / strength | 重要性或偏好强度 | REAL，0–1；不是模型自信心的伪装 |
| source | 记忆来源 | owner_explicit、conversation、video、reflection 等 |
| source_event_id | 事实证据 | 可空；存在时必须引用 event.id |
| status | 工作流状态 | 只能取对应表定义的枚举 |

## 3. M0 已有核心表

### 3.1 schema_migrations

| 字段 | 类型 | 说明 |
|---|---|---|
| version | INTEGER PK | 已应用的 schema 版本 |
| applied_at | TEXT | 应用时间，UTC |

同时维护 PRAGMA user_version。升级前必须冻结写入、快照、核对行数/时间戳/大小；校验失败直接退出。

### 3.2 event

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 事件 UUID |
| ts | TEXT | 发生时间 |
| actor | TEXT | 行为者 |
| kind | TEXT | 如 user.message、assistant.message、model.error、correction、circuit_breaker.triggered |
| payload | TEXT JSON | 事件参数；消息事件至少含 content，主动消息另含 client_id、channel |

索引：idx_event_ts(ts)、idx_event_kind_ts(kind, ts)。BEFORE UPDATE 和 BEFORE DELETE 触发器均 abort，错误文本含 append-only。列表接口按 ts DESC、rowid DESC 返回。

常用 payload：

- user.message：{"content":"...","client_id":"desktop"}。
- assistant.message：{"content":"...","client_id":"desktop","channel":"chat|share"}。
- correction：{"target_event_id":"...","rule_id":"...","reason":"...","expected":"...","appeal_status":"open|accepted|rejected"}。
- circuit_breaker.triggered：{"rule_id":"...","scope":"...","evidence_ids":[...],"action":"..."}。

### 3.3 memory 与 memory_fts

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 记忆 UUID |
| kind | TEXT | profile、preference、promise、fact、feeling 等 |
| who | TEXT | 与谁有关；核心关系人数限制在业务层执行 |
| content | TEXT | 一句可独立理解的事实，如“主人连续三天加班到 22 点后” |
| weight | REAL | 默认 0.5，范围 0–1 |
| ts | TEXT | 记忆形成时间 |
| source | TEXT | 来源类别 |
| source_event_id | TEXT FK NULL | 证据事件 |

memory_fts 是 external content FTS5 表：content='memory'、content_rowid='rowid'、tokenize='trigram'。INSERT、UPDATE、DELETE 触发器同步索引。相同 kind + who + content 重复写入时返回已有记录，不重复堆积。

查询规则与当前 M0 实现一致：q 去空格后为空则返回空；少于 3 个字符用参数化 LIKE 兜底；其余把整句作为 FTS5 phrase 查询，再按 weight DESC、ts DESC 限制条数。q 永远使用绑定参数，不拼接 SQL。

### 3.4 state

| 字段 | 类型 | 说明 |
|---|---|---|
| key | TEXT PK | 投影键 |
| value | TEXT JSON | 类型化 JSON 值，不能统一当字符串解释 |
| updated_at | TEXT | 最近更新时间 |

v1 键约定：

| key | JSON 类型 | 默认/枚举 | 用途 |
|---|---|---|---|
| energy | number | 0–100，初始 100 | 低时句短、主动减少；耗尽进入睡眠 |
| mood | string | 初始“平静” | 表达状态，不代替价值判断 |
| presence | string | 在、忙碌、离开 | 是否在场 |
| sleeping | boolean | false | 睡眠不是离线，也不是死机 |
| started_at | string | 首次启动 UTC | 存在连续性证据 |
| last_heartbeat | string | 最近心跳 UTC | 离线判定 |
| satiety | number | M1 可选，0–100 | “会饿”的外显；缺省时壳端不展示 |
| muted | boolean | M1 可选，false | 静音陪；不阻止主人主动聊天 |

未知键必须保留但可被客户端忽略；客户端不得因为缺一个可选键而清空整份状态。

### 3.5 intent

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 意图 UUID |
| content | TEXT | 想做什么、答应了什么 |
| status | TEXT | open、done、cancelled、blocked |
| created_at | TEXT | 创建时间 |
| due_at | TEXT NULL | 到期时间；空表示未承诺日期 |

完成或取消必须追加事件。到期未处理不能被后台静默删除。

### 3.6 ledger

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 调用账目 UUID |
| ts | TEXT | 调用时间 |
| kind | TEXT | chat、vlm、image、asr、tts、review |
| tokens_in / tokens_out | INTEGER | 输入/输出 token；非 token 模型记 0 |
| cost | REAL | 实际可核成本；本地调用可记 0，不伪造精确价格 |

建议另以 event payload 记录 model_id、task_id、latency_ms、fallback_from，避免改 v1 表结构时丢失排障信息。

### 3.7 autobiography

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 周记录 UUID |
| week | TEXT | ISO 周，如 2026-W44 |
| change | TEXT | 本周观察到的变化 |
| evidence_ids | TEXT JSON | 支撑变化的事件/偏好 ID 数组 |

每周只提炼三五条，有证据才写。价值观和红线不能由该表自动改写。

### 3.8 voice

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 观点 UUID |
| ts | TEXT | 形成时间 |
| source_url | TEXT NULL | 关联公开内容，仅用于依据，不代表要公开发布 |
| stance | TEXT | 她自己的立场或评价 |
| mood | TEXT NULL | 当时状态 |
| basis_ids | TEXT JSON | 观看、抽帧、字幕、评论等依据 ID |
| status | TEXT | draft、kept、dropped、shared_private |

status=dropped 的条目要定期让主人看到，不能出现“想说但没地方说”。v1 的 shared_private 仅指私下给主人链接与评价。

### 3.9 artwork

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 作品 UUID |
| path | TEXT | 受管产物路径，不接受任意外部写入路径 |
| prompt | TEXT | 完整提示词，含固定画风前缀 |
| reason | TEXT | 为什么画 |
| mood | TEXT NULL | 创作时状态 |
| created_at | TEXT | 创建时间 |

每月自画像引用同一问题和固定参考，便于并排观察变化。

### 3.10 preference

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 偏好 UUID |
| topic | TEXT | 话题或对象 |
| polarity | TEXT | like、dislike、neutral |
| strength | REAL | 0–1 |
| evidence_ids | TEXT JSON | 行为或表达证据 |

偏好从主动接近、回避、回复长短等选择中生长；单次露脸不足以推断喜欢。

### 3.11 letter

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 信件 UUID |
| ts | TEXT | 交付时间 |
| from / to | TEXT | 发送者与接收者；SQL 中列名需加双引号 |
| content | TEXT | 信件正文 |

与喵酱的通信若未来发生，只能经由此表显式传递；两个项目不做记忆同步。未启封的信在主人启封前不得写入可被模型检索的 letter。

### 3.12 handover

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | 交接页 UUID |
| day | TEXT | 本地日期 YYYY-MM-DD；仅作分段标签 |
| content | TEXT | 几十行内：发生什么、承诺、未完事项、心情 |
| evidence_ids | TEXT JSON | 对应事件范围 |
| created_at | TEXT | 封存时间，UTC |

每天 03:00 本地时间随备份封存一段。摘要最多两级，新段开头优先读最近交接页而不是全文。

## 4. v1 分享扩展表 share_queue

该表是 M4 目标；在 M0 库中尚不存在时由下一 migration 添加，不能假设已随核心 schema 建好。

~~~sql
CREATE TABLE share_queue (
  id TEXT PRIMARY KEY,
  source_platform TEXT NOT NULL,
  external_id TEXT,
  source_url TEXT NOT NULL UNIQUE,
  title TEXT NOT NULL,
  summary TEXT NOT NULL,
  comment TEXT NOT NULL,
  basis_ids TEXT NOT NULL,
  status TEXT NOT NULL CHECK(status IN ('pending','sending','sent','skipped')),
  discovered_at TEXT NOT NULL,
  next_attempt_at TEXT NOT NULL,
  attempt_count INTEGER NOT NULL DEFAULT 0,
  batch_id TEXT,
  outbound_event_id TEXT REFERENCES event(id),
  skip_reason TEXT,
  last_error TEXT,
  sent_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_share_queue_dispatch
  ON share_queue(status, next_attempt_at, discovered_at);
~~~

sent 只表示对应出站 event 已可靠落库，不表示主人已读。详细调度见 docs/share_queue_design.md。

## 5. 关系层级与隐私

- 核心：不超过 5 人，可保存互动、脾气、承诺与安慰方式。
- 熟人：不超过 20 人，只存名字和少量印象。
- 面孔：其余只有昵称或不记；出现次数不能替代直接互动。
- 主人的约 100 人群属中群，但 v1 不做全量监听和全量记忆。
- 私聊、银行、密码窗口及明确黑名单材料不得进入视频理解或记忆索引。

## 6. 备份、恢复与完整性

每天 03:00 本地全量备份数据并保留 14 天；每周日异地保留 8 周；每半月离线冷备保留 12 份；升级前快照永久保留。登录态另行加密保管，不混入普通数据库备份包。

健康检查执行 PRAGMA integrity_check，非 ok 时返回 503、冻结写入并告警。每月恢复演练至少验证：数据库可打开、schema_version 一致、event 行数、最新时间戳、FTS5 中文检索和最近一段交接页。恢复只搬数据，不与模型或 schema 升级同时进行。
