# 灵鲸鲸桌面壳状态机 v1

> 适用范围：miao-shell / PWA 的展示与连接逻辑。壳只画界面和发请求，不在进程内直接调用大脑服务。
> 默认大脑地址：http://127.0.0.1:7100。所有 HTTP 请求带 X-Ling-Token；开发令牌 lingjingjing-local-dev 仅限本机回环。

## 1. 状态分层

不要用一个枚举同时表示所有事。壳端维护三组互相独立的状态：

1. connection：BOOT、CONNECTING、ONLINE、OFFLINE、FAULT。
2. activity：IDLE、THINKING、SPEAKING、SLEEPING。
3. overlay：DRAGGING、MUTED、QUIET_HOURS，可同时存在，不覆盖 connection。

大脑的 sleeping 是灵鲸鲸的生活状态；壳的 OFFLINE 是连接状态。二者绝不能混用。主人拖动桌宠只改变 overlay，不应清空对话或重连。

## 2. 状态含义与进入条件

| 状态 | 进入条件 | 外观与行为 | 离开条件 |
|---|---|---|---|
| BOOT | 壳进程刚启动 | 显示“正在醒来”，禁用重复发送 | 读取本地配置后进入 CONNECTING |
| CONNECTING | 启动或收到重连信号 | 先 GET /v1/health，再取 state/events | 全部通过进入 ONLINE；失败按退避重试 |
| ONLINE / IDLE | 连接健康、无生成任务 | 显示 state 的 mood、energy、presence；允许输入 | 发消息进入 THINKING；sleeping=true 进入 SLEEPING |
| THINKING | 已发送 POST /v1/chat，尚未收到终态 | 锁定该客户端重复提交；仍允许主人取消等待提示 | 成功则展示回答并进入 SPEAKING 或 IDLE；失败回到 IDLE/OFFLINE |
| SPEAKING | 有文本或语音正在播放 | 文本立即出现；语音可停止，不强制播完 | 播放结束或被主人停止后回 IDLE |
| SLEEPING | state.sleeping=true 或 energy=0 | 降低动画与主动提示；不是“离线” | 主人主动说话可唤醒请求；state 恢复后回 IDLE |
| OFFLINE | 连续 3 次连接失败，或心跳陈旧且请求失败 | 显示“暂时联系不上大脑”，保留本地草稿与最近 7 天只读缓存 | 健康检查与状态读取成功后回 ONLINE |
| FAULT | 数据库完整性错误、认证配置错误等不可自动修复问题 | 给出明确错误与处置，不无限自动重试 | 主人修复后手动重连 |
| DRAGGING | 鼠标/触摸拖动桌宠 | 只移动窗口，显示轻微反馈 | 松开即清除 overlay |
| MUTED | 主人开启静音陪 | 不主动弹文字/语音；仍保留可见状态 | 主人关闭静音 |
| QUIET_HOURS | 当前处于主人设定安静时段 | 主动分享暂存，不弹窗；主人消息仍正常回应 | 离开时段或主人临时允许 |

## 3. 启动与轮询时序

HTTP 基线流程不依赖额外接口：

1. BOOT：读取本地配置，绝不把令牌写入日志或截图。
2. CONNECTING：GET /v1/health。401 进入 FAULT 并提示检查令牌；503 区分数据库故障与模型故障。
3. 健康后并行读取 GET /v1/state 与 GET /v1/events?limit=50，按 event id 本地去重，再进入 ONLINE。
4. 在线时每 5 秒读 state；每 2 秒读 events?limit=50。窗口隐藏时可降到 15 秒，但发送消息后立即恢复。
5. 壳保存 last_seen_event_id 集合，而不是假设“最新一条一定没看过”。events 按时间倒序返回，渲染前重新按时间正序排列。
6. 当前实现扩展 /v1/ws 可用于减少轮询，但断线后必须能回退到上述 HTTP 流程；WebSocket 不是核心契约的必要条件。

心跳默认 15 秒。last_heartbeat 超过 45 秒只标记“疑似陈旧”；必须再配合真实请求失败才能进入 OFFLINE，避免壳端时钟偏差误判。

## 4. 聊天事务

发送时生成壳端 local_message_id，仅用于本地显示，不改变固定请求体：

    {"message":"主人输入","client_id":"desktop"}

成功响应后：展示 reply；以服务器 state 覆盖本地投影；把 user_event_id、assistant_event_id 加入已见集合；memories 只用于可选的“她想起了什么”面板，不插入聊天正文。

失败处理：

- 400/422：保留输入，显示具体校验问题，不自动重复提交。
- 401：进入 FAULT，禁止用猜测值暴力重试。
- 503：显示“大脑或模型暂时不可用”，保留草稿；是否自动重连由退避策略决定。
- 网络中断：本次结果未知。先拉取 events 按内容和本地时间窗核对，不让用户毫无提示地连点重复发送。

## 5. 主动分享与事件渲染

灵鲸鲸的私下分享由大脑写 assistant.message 事件，payload.channel='share'，并带 client_id。壳轮询到后像普通她的消息一样展示，但不伪装成主人刚发起过对话。

壳端收到重复 event id 必须去重；本地已展示集合用于至少一次传输下的幂等。事件的 sent 不表示已读，壳不额外新增 HTTP 回执接口。QQ 或手机适配器也各自维护去重状态。

MUTED 或 QUIET_HOURS 下，分享仍保留在消息列表，但不弹窗、不播放提示音。主人打开窗口可以看到，避免“想说但没地方说”。

## 6. 退避与降级

连接重试间隔依次为 1、2、5、10、30 秒，之后每 60 秒一次；每次加少量随机抖动。401 不参与退避，数据库完整性失败也不自动反复重启。

离线时可查看最近 7 天缓存和本地草稿；不能看新视频、不能查新资料、不能生成新图片或语音。缓存明确标为“旧内容”，不得伪造新的心跳、心情或回答。模型 API 挂而大脑健康时，大脑可按模型清单切备用 provider，壳只展示降级提示。

## 7. 状态对表达的影响

- energy 高：可有较长动画和较多主动表达，但仍受每天主动不超过 3 次限制。
- energy 低：动画简化、句子偏短，只回重要内容。
- energy=0 / sleeping：显示睡觉，不显示掉线或错误红屏。
- mood：只改变表情与节奏，不覆盖红线，也不作为惩罚主人的理由。
- satiety 缺失：隐藏“饿”的图标，不自行假设数值。

## 8. 最小验收

1. 杀死后端：45 秒疑似提示后，结合实际失败进入 OFFLINE；本地草稿仍在。
2. 恢复后端：不需重启壳即可回到 ONLINE，事件不重复。
3. sleeping=true：界面显示睡眠而非离线，主人仍能发消息。
4. 拖动、静音、安静时段可叠加，互不清除。
5. 401、422、503 分别可理解，日志无令牌。
6. 同一分享事件连续出现两次，壳只展示一次；静音时可在消息列表找回。
