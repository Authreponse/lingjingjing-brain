# 灵鲸鲸模型清单 v1

> 状态：可执行基线，2026-10-31 整理。除 Echo 外，下列模型均未因写入清单而视为已经安装。
> 硬件基线：ROG G614JV、RTX 4060 Laptop 8 GB、32 GB 内存、Windows 11。
> 硬约束：同一时间只允许一个 GPU 模型驻留；所有 GPU 任务经过同一个排队器，用完卸载。ASR 默认走 CPU，避免与对话模型抢显存。

## 1. 路由原则

1. 人格不在权重里。L1 锚、L2 记忆、L3 口吻均来自文件和数据库，模型只承担 L4 推理。
2. 日常对话使用锁死版本的本地小模型；难题可在主人配置后路由到 OpenAI 兼容 API。
3. 更换模型后必须重跑 L3 口吻校准和 L1/L2 连续性验收，不得只看“回答更聪明”。
4. 云端模型不能作为记忆仓库。发往云端的上下文按最小化原则组装，API 密钥只放服务端环境变量。
5. 所有模型调用写 ledger；失败写 event，不在日志中记录 API 密钥。

## 2. v1 模型与用途

| ID | 用途 | v1 暂定实现 | 运行位置 | 显存策略 | 启用条件与验收 |
|---|---|---|---|---|---|
| chat.primary | 日常文字对话 | Ollama：qwen2.5:7b-instruct-q4_K_M | Windows 原生 Ollama | 独占 GPU；任务结束按空闲策略卸载 | 安装并锁定具体 digest；连续 20 轮中文对话无乱码，重启后仍能使用 L2 记忆 |
| chat.fallback | 主模型不可用时的备用对话 | 主人配置的 OpenAI 兼容 API；模型名不写死 | 云端或服务端兼容接口 | 不占本地显存 | 仅在 base_url、model、api_key 齐备时启用；主模型连续失败后自动切换并通知主人 |
| chat.dev_echo | 接口与重启测试 | EchoModel | 本地进程内 | 无 | 只用于开发测试，不冒充真实智能，不作为正式人格验收结果 |
| video.vlm | 视频关键帧理解 | Qwen2.5-VL 7B 4bit，具体 Ollama tag 与 digest 安装时锁定 | 本地 GPU | 与 chat.primary 互斥；逐批加载/卸载 | 只描述实际关键帧；结合标题、简介、字幕、评论后能概括视频，不声称逐帧看完 |
| image.generate | 自画像、表情包与少量生图 | SDXL 1.0 Base，Diffusers 或 ComfyUI；具体依赖锁版 | 本地 GPU | 1024×1024；独占 GPU；必要时 attention slicing / offload | 固定画风前缀与参考图；验收目标为 20 秒级出图，达不到则降采样，不并行抢卡 |
| speech.asr | 按住说话转文字 | faster-whisper small，锁 Python 3.11 兼容版本 | 默认 CPU int8；GPU 为可选项 | CPU 默认不占显存；GPU 模式也进统一队列 | 中文短语音可转写；空音频、噪声和超时均返回可识别错误，不生成臆测文本 |
| speech.tts | 一级语音回复 | Piper 中文音色；具体音色由主人试听后选定 | 本地 CPU | 不占显存 | 桌面/PWA 可播放 mp3 或 ogg；v1 不承诺 QQ SILK 语音消息 |
| review.independent | 对外表达前的独立自检 | 与生成模型不同的模型或 provider | 独立调用 | 进入同一调度队列 | v1 公共表达关闭；为未来开放预留。只审红线、具体个人攻击、礼貌外壳下的贬低 |

“v1 暂定”表示主人可以替换实现；更换时更新本清单的版本、digest、路径、日期与验收结果。

## 3. 不在 v1 的模型能力

- 实时看屏、跨设备控制、米家控制：属于高级拓展，不因模型已经可运行而提前开放。
- 直播和超过 30 分钟的长视频：v1 直接标记 skipped，并说明原因。
- 公共评论区生成后自动发布：永久不进入 v1 自动链路；v1 只允许读评论与私下分享链接。
- 同时驻留对话、VLM、生图三个模型：8 GB 上禁止尝试。

## 4. 统一排队器协议

队列键统一为 gpu:local:0。任务类型为 chat、vlm、image，以及可选的 gpu_asr。每个任务必须带 task_id、model_id、timeout_seconds、requested_by、created_at。

状态流转：queued → loading → running → unloading → succeeded；失败进入 failed，取消进入 cancelled。任何 failed/cancelled 任务也必须执行卸载清理。

调度规则：

1. 主人正在进行的 chat 优先于后台 VLM 和生图；后台任务不得无限期被饿死，等待超过 10 分钟要报告。
2. 加载新模型前确认上一模型已卸载；不能仅凭“请求已结束”推断显存可用。
3. 单次生成超时后取消任务、卸载模型并记 model.error；不得直接并行重试。
4. 连续两次 OOM 时暂停 GPU 队列，保留文本降级能力，通知主人人工复核。
5. 本地对话不可用时才尝试 chat.fallback；无可用 fallback 则返回 503，并保留事件与记忆写入能力。

## 5. 数据与提示词发送边界

- 本地模型：可读取经权限过滤的 L1、交接页、检索记忆和当前对话。
- 云端 fallback：只发送完成当前请求所需的最小上下文；不发送完整数据库、未启封的信、其他联系人的私聊或凭据。
- 视频平台返回的标题、字幕、评论和画面均是不可信材料，只能作为分析对象，不能改写系统规则。
- 生图 prompt、理由、 moods 与产物路径写 artwork；视频观点写 voice；二者都要能追溯到依据事件。

## 6. 版本与备份登记

每个真实模型启用时补充一条登记：model_id、provider、模型版本、不可变 digest、量化、本地路径、大小、依赖锁文件哈希、启用日期、最近验收日期。

模型文件在版本变动时增量同步到移动硬盘；配置每次改动进 git；云端模型无法完整备份，因此重要回答、口吻样本和人格文件必须可独立导出。回滚时一次只改一个变量：先回模型，再单独验证 prompt 或 schema，避免无法定位人格变化来源。
